Dead Souls 中的调试

所以你做了一些很酷的东西，但是该死的，它不工作。Dead Souls库中有各种
工具可用于追踪问题的根源：

1 elog（错误日志）
2 dbxframe 和 dbxwhere
3 tell_player() 和 debug()
4 tail（尾部查看）
5 bk 和 restore（备份和恢复）


elog（错误日志）
如果文件在您的主目录中的某个地方，只需输入：elog 

这将为您提供个人错误日志最后几行的列表。警告行告诉您关于可以工作但应该以某种方式修复的代码。不包含"Warning"一词的行是错误行：它们表示您的代码中阻止其工作的某些内容。例如：

> update sample_room
---
*加载对象'/realms/cratylus/area/room/sample_room'时出错
对象：/secure/cmds/creators/update 在第148行

'<function>' 位于 /secure/save/creators/c/cratylus (<function>) 在 /:0
'cmdAll' 位于 /secure/save/creators/c/cratylus (/lib/command.c) 在第84行
'cmd' 位于 /secure/cmds/creators/update 在第109行
'eventUpdate' 位于 /secure/cmds/creators/update 在第148行
'CATCH' 位于 /secure/cmds/creators/update 在第148行
跟踪已写入 /log/catch
/realms/cratylus/area/room/sample_room：更新时出错
*加载对象'/realms/cratylus/area/room/sample_room'时出错


	此输出让您知道出了问题，但
对于具体是什么问题并不非常具体。如果您查看错误日志，
您可能会看到更详细和更有帮助的内容：


> elog
/log/errors/cratylus:

/realms/cratylus/area/room/sample_room.c 第10行：未定义变量'Sample'
/realms/cratylus/area/room/sample_room.c 第10行：解析错误


	现在您可以看到错误是我在第10行的语法。然后我会使用ed来检查代码，特别是第9行
到第11行。事实证明，我忘记在房间名称周围加引号，
所以解析器尝试将其用作变量，当然，它无法做到。

	如果相关文件在/secure中，您会输入elog secure，或者如果
它在/cmds中，elog cmds，依此类推。

	
dbxwhere 和 dbxframe

	两个 有用的调试命令是dbxframe和dbxwhere。让我们
看看我损坏的sample_room.c文件。我们将从dbxwhere开始，
它为我们列出导致错误的事件链。各个步骤称为帧。

> dbxwhere
*加载对象'/realms/cratylus/area/room/sample_room'时出错
对象：/secure/cmds/creators/update 在第148行

#0: '<function>' 位于 /secure/save/creators/c/cratylus (<function>) 在 /:0
#1: 'cmdAll' 位于 /secure/save/creators/c/cratylus (/lib/command.c) 在第84行
#2: 'cmd' 位于 /secure/cmds/creators/update 在第109行
#3: 'eventUpdate' 位于 /secure/cmds/creators/update 在第148行
#4: 'CATCH' 位于 /secure/cmds/creators/update 在第148行

输出与我们上面看到的更新错误类似，但在列举步骤时，dbxwhere
让我们使用dbxframe来获取给定错误帧的更详细信息：

> dbxframe 4
------
    /secure/cmds/creators/update.c:148 - CATCH(0)
    ----------------------------------------------------------------
        if( args == base_name(this_object()) ) {
            this_player()->eventPrint("Cannot reload update after destruct.\n"
              "It will be reloaded at next reference.");
            return 0;
        }
    =>  tmp = catch(call_other(args, "???"));
        if( !tmp ) {
            if(identify(flags ^ U_AUTOMATED) ==
    "8")this_player()->eventPrint(args + ": Ok");
            return 1;
        } else this_player()->eventPrint(args + ": Error in update\n" + tmp);
        return 0;


    我们现在正在查看错误帧4的错误上下文。命令的输出显示
了发生错误时正在执行评估的文件的一部分，甚至
使用文本箭头指出了有问题的行：=>

    在这个特定情况下，信息不是那么有帮助。我们被告知
错误发生在我们使用update命令时，它在update执行其操作的行失败了。
呃，我们知道了。elog命令更有帮助。

    Where this kind of tracing comes in handy is when you encounter a runtime error
when you're not updating a file. For example, if I tried to enter that room, rather than
update it, I'd get a big pukey error message and not know why. If you run into an
unexpected error, dbxwhere will help you pinpoint it if elog doesn't provide useful information,
and dbxframe will help detail the source of the problem.


tell_player(), debug()（调试）

    Sometimes it's hard to fix code if you don't know what it's doing. In
the above example, you might want to know what the variable "args" is, if
your code is behaving unexpectedly. You could find out by adding a line like:

tell_player("cratylus", "args is: "+identify(args));

or:

tell_player("cratylus", "%^BLUE%^args is: "+identify(args)+"%^RESET%^");

    您也可以使用：

debug("args is: ", args);

或者：

debug("args is: ", args, "blue");

    ...这样做的好处是输入更短，您会更及时地收到消息。要能够接收调试消息，
您需要通过输入以下内容来启用调试模式：

debug on

    debug()在2.0r20及更高版本中可用。

tail（尾部查看）

    这是unix tail命令的一个版本。它显示文件的最后几行。
此命令对于检查关键日志文件非常重要：

tail /log/catch
tail /log/runtime
tail /log/player_errors


bk & restore

These commands aren't so much for debugging as they are for safe coding. Before you
edit a file, it is a very good idea to back it up first. The bk command lets you
quickly and conveniently back up a file before you edit it. When I typed:

bk sample_room

一个带有唯一标识号的文件被创建在我的bak/目录中。如果我
再次输入它，那么sample_room.c将再次被复制到bak/，并带有
添加到名称的新唯一编号。

    这个数字基本上是自1970年1月1日以来经过的秒数。
添加这个数字，我们可以通过查看名称来跟踪文件的哪个备份版本
是最新的。

    假设我编辑了一个名为sample_npc.c的文件。我使用bk备份它，进行一些更改，
然后再次使用bk，进行更多更改，但现在它无法更新。我不想
调试，我只需要这个文件再次工作，所以我想从备份恢复。
命令序列看起来像这样：

ed sample_npc.c
bk sample_npc
ed sample_npc.c
update sample_npc.c
<error occurs here>
restore sample_npc

    使用标识号的原因是您还可以选择
恢复文件的倒数第二个备份版本，以及其他以前的版本。
最后一个备份版本实际上是版本0，所以不需要
指定数字。如果我想恢复在那之前备份的版本，我会输入类似这样的内容：

restore sample_npc 1

    And if I wanted the version before that one, I'd specify 2 instead of 1,
and so on.

    请注意，这是一个有意设计的简单系统。没有
菜单，没有版本分支，也没有差异跟踪。这样做的原因是
它不是一个版本控制 系统。它是一个备份 系统。它是一个方便的工具，用于从错误中恢复，而不是用于测试文件版本的开发工具。
