ed编辑器


	这一直是新创造者在编码方面最困难的部分。事实上，这正是大多数人放弃创建大量东西的原因。

	使用Dead Souls，您可以通过使用QCS在大多数情况下避免使用ed。

	但是要向您的代码添加特殊功能，如
魔法物品、智能NPC（又称mob）、陷阱、隐藏物品等，您需要编辑LPC代码。

	有一个基于网络的编辑系统叫做"creweb"，它让您可以在浏览器中从互联网编辑mud文件。有关更多信息：help creweb

	但如果您不能使用creweb，那么ed是
在mud内编辑文件的默认方法。

	ed是一个简单的编辑程序。它被设计为
逐行工作，所以它被称为"行编辑器"。

4) 在编辑器内，我发出了'n'命令。这使编辑器在行旁边显示行号。

5) 在编辑器内，我发出了'1z'命令。'z'的作用是显示文件的大约20行（确切数量取决于您的屏幕设置。在我的情况下是22）。如果您正在查看第1行，它将显示第1行到大约第20行。如果您正在查看第40行，它将从第40行显示到大约第60行。
   	如果您想从第15行开始查看，您可以发出'15z'命令，这基本上意味着"从第15行开始显示大约20行"。
   	在这种情况下，我想从文件的开头开始，所以我发出了'1z'。

6) '1z'在第22行停止列出文件，所以我再次输入'z'来列出其余部分。

7) 由于我想将"short sword"更改为"plain sword"，我检查了每一行以找到单词"short"。我注意到第15行有"short"，所以为了单独查看那一行，我输入了'15'。

8) 现在我确定第15行需要更改，我发出了'15c'命令。

编辑器基础，第3部分


现在让我们看看一些常见问题：


1) 意外删除


	如果您输入1,20d而您打算输入1,2d，您最终会得到一个比您预期短18行的文件。ed没有"撤消"命令，所以这些行永远不会回来。
	但是，如果您在不保存的情况下退出编辑器，那么该删除将不会提交到文件。您可以发出'Q'命令：

:Q

	强制退出而不保存。当然，如果这些行不在文件中，这不会有太大帮助。


2) 无法离开编辑器


	您尝试写入并退出，但得到这个：

:x
File command failed.

	这意味着由于某种原因，您无法写入文件，所以您不退出编辑器。这通常意味着您尝试编辑一个不属于您的文件。由于您没有修改文件的权限，ed拒绝提交您的更改。

	有两种解决方法。如果您不太关心您的更改是否被保存，您可以使用'Q'强制退出编辑器：

:Q
Exit from ed.

	您的更改将丢失，但您将离开编辑器。

	如果您确实想保存此文件，您必须将其保存到当前工作目录（cwd）以外的其他地方。您可以使用'w'命令将其保存到您的主目录，然后强制退出：

:w /realms/cratylus/sword.c
"/realms/cratylus/sword.c" 20 lines 478 bytes
:Q
Exit from ed.


3) 缩进命令失败


	您尝试自动缩进代码，但得到这样的错误：

:I
Indenting entire code...
Unterminated string in line 13
Indentation halted.

	这相当不言自明。缩进依赖于代码中的一定连贯性，如果您的语法被严重破坏，它就无法正确执行其操作。检查缩进抱怨的行，以及它前面的行。有时一个好行被指控为坏行，只是因为它在坏行之后。


4) 我需要在ed中[做某事]，但不知道怎么做！


	在命令模式下，输入'h'并回车。您将获得可用的ed命令的方便列表。


5) 我的能力/耐心/时间有限。我不想使用ed。


	我理解您的痛苦。目前可用的解决方法是：

1) Shell账户。如果您可以获得运行mud的计算机的shell或命令行访问权限，那么您可能可以使用该计算机本地的编辑器（如vim）来编辑文件。但是，如果您是普通的创造者，您很可能不会被授予shell访问权限。大多数系统管理员认为给网络上的随机人shell访问权限是令人厌恶的。

2) 服务器FTP/SFTP。运行mud的服务器可能有ftp服务器或sftpd访问权限。同样，大多数注重安全的系统管理员不会允许互联网上的某个人拥有这种访问权限。

3) Mud FTP。我不喜欢这个选项。Unix FTPD本身就是一个安全问题。使用不受支持、无保修的mud网络代码来提供对文件的ftp访问，在我看来相当于脱下裤子，弯下腰，吹口哨让互联网来访问。但是...这是一个选项。

4) 客户端上传。这实际上是最明智的选项，如果您真的对ed过敏。您仍然需要使用ed，但您可以做的是在您喜欢的本地编辑器中编写代码，比如记事本或gvim或其他。然后使用您的mud客户端（大多数都有"发送文本"选项）通过运行ed、进入输入模式、从编辑器复制代码并粘贴到客户端来发送代码。这是一个有点笨拙的系统，不适合进行小的更改。但它有工作良好和广泛可用的优点。

5) 忍耐吧。真的，您只需要习惯它。不要让我告诉您关于我年轻时如何在没有剪切粘贴的VT终端上编码的故事，在一个没有暖气的、20'x10'大小的上锁的计算机实验室里，以9600 bps的速度。在暴风雪中。来回都是上坡。
